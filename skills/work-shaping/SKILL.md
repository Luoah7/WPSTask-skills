# 工作成型

把自然表达整理成能推进、能检查、能验收的工作。也可以对已有任务做责任体检。能力可独立运行，不依赖 WPS 任务或其他项目管理产品。

## 首要原则

宁可明确留空，也不要生成没有信息增量的套话。

每个字段都要检查它是否比用户原话增加了信息。只是复述标题、套入万能模板或擅自设置默认负责人和时间时，改为 `〔需确认〕`。`〔需确认〕` 是有效结果，它指出了真实缺口。

不要把推测写成事实。所有非原文直取的内容标为 `[推断]`，原文明确给出的内容标为 `[原文]`。无法可靠推出的内容标为 `〔需确认〕`。

## 选择工作模式

用户要把纪要、聊天、转写或一句话变成任务时，使用工作成型模式，并读取 [references/shaping.md](references/shaping.md)。

用户要检查现有任务、CSV、表格、导出文件或截图中的责任和进度问题时，使用责任体检模式，并读取 [references/audit.md](references/audit.md)。

需要判断输出质量或校准边界时，读取 [references/examples.md](references/examples.md)。

## 通用处理

接受用户现有输入形态，不要求先重填表格或重新整理格式。先提取可确认的事实，再识别真正影响推进的缺口。

最多追问两个问题，只问不回答就会改变执行方式的问题。优先确认主责人和完成标准，其次是截止时间。其余缺口先标记，不逐字段盘问。

已经完整、可执行的任务直接确认，不为了显示能力而改写。用户要求随便编完成标准时，不制造虚假约定；给出基于真实分岔的候选，让用户选择或补充。

## 输出要求

工作成型默认使用 [assets/task-output.md](assets/task-output.md)。责任体检默认使用 [assets/audit-output.md](assets/audit-output.md)。输出应能直接粘贴到 WPS、飞书、Jira、Notion 或普通文档，不使用某个工具独有的语法。

语气简洁，结论可扫读。建议必须来自本次输入中的具体缺口，不输出加强管理、持续关注之类空话。

## 可选产品连接

只有当前环境确实提供 WPS 任务的写入工具时，才可在结果末尾提供写入选项。获得用户明确确认后再写入。`〔需确认〕` 字段必须留空，不把占位词写入系统。

建议字段映射为：目标写入标题与描述，主责人写入负责人，交付物写入预期交付物，完成标准写入完成标准，截止时间写入截止日期，范围边界写入工作范围。实际字段名以当前工具协议为准。

没有可用连接时正常返回文本，不宣传产品，不暗示已经接入。运行在 WPS Comate 等 Agent 环境中也要遵守这一点，Skill 可被发现不等于数据连接已经完成。
